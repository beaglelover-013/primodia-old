# 普利莫迪亚 SLG 角色日程伪活化灵感计划

状态：灵感记录，暂不实现。

## 目标

让配角不只是静态变量，而是拥有类似 SLG 的生活节奏：上班、回家、逛街、来酒馆、离开当前场景等。

这套系统不追求完全模拟世界，而是让角色看起来有自己的日常，并且不会和当前剧情冲突。

## 核心想法

角色日程不是强制命令，而是默认倾向。

- 如果角色不在主角同一场景，可以按日程在后台移动。
- 如果角色正在和主角同场景互动，日程不直接把她移走，而是变成叙事提醒。
- AI 负责自然处理提醒，例如告辞、犹豫、改约、留下、迟到。
- 最终位置仍然以变量为准。

## 需要先补的基础

### 当前同场景人物

前端需要根据变量判断谁和主角在同一个地点。

参考来源：

- `主角.所在位置`
- `世界.当前地点.具体位置`
- `人物羁绊.角色名.所在位置`

生成发送包时只把同场景人物作为“当前可见人物”交给 AI。

不在同场景的人，不应该被 AI 当成正在眼前的人描写。

示例：

```yaml
当前同场景人物:
  - 橘柒:
      所在位置: 主厅接待区
      当前状态: 正在和主角聊天
      心情: 好奇，但有点犯困
```

## 日程提醒逻辑

### 不同场景

如果角色不在主角所在地点，日程可以后台结算。

示例：

```text
当前时间 09:00。
莉娅日程命中：去面包坊上班。
莉娅不在主角当前场景。
前端可以把 莉娅.所在位置 更新为 面包坊。
```

### 同场景

如果角色正在当前场景，就不要直接瞬移。

示例：

```text
当前时间 16:00。
橘柒日程命中：应该回一号房。
但橘柒当前正在和主角同场景互动。
发送给 AI 的提醒：
橘柒原本该在 16:00 回房。请自然处理她是否告辞、犹豫留下，或因玩家行动改变计划。
```

## 可能的数据格式

日程可以以后放在世界书条目里，便于修改。

```yaml
<PrimordiaNpcSchedule>
橘柒:
  默认地点: 一号房
  日程:
    - 名称: 上午来酒馆蹭饭
      星期: [六]
      开始: "08:00"
      结束: "15:00"
      地点: 主厅接待区
      行动: 蹭热食，顺手帮忙擦桌
    - 名称: 下午回房
      星期: [六]
      开始: "15:00"
      结束: "23:00"
      地点: 一号房
      行动: 把自己裹在旧斗篷里睡觉
</PrimordiaNpcSchedule>
```

## 发送包建议

不要把完整日程表全部塞给 AI。

前端应该先算出结果，再只发送当前相关内容。

```yaml
当前可见人物:
  橘柒:
    所在位置: 主厅接待区
    当前行动: 正在和主角聊天

日程提醒:
  - 橘柒原本该在 16:00 回一号房，但她当前仍在主厅接待区和主角互动。请自然处理她是否离开或留下。
```

## 暂不做的内容

- 不做复杂 AI 自主规划。
- 不让 AI 自己判断角色应该在哪。
- 不直接大规模改世界状态。
- 不让日程强行打断所有剧情。

## 暂缓备忘：人物随身钱

后续可以考虑给 `人物羁绊` 中的角色增加自己的随身钱字段，用来支持借钱、发工资、攒路费、NPC 自主消费等玩法。

第一版不做复杂多币种，只记录一个轻量字段即可：

```yaml
人物羁绊:
  角色名:
    随身钱:
      折算合计铜币: 0
```

这个字段暂不进入正式变量结构，先作为未来设计备忘。

## 第一版如果要做

优先级建议：

1. 做“当前同场景人物”判断。
2. 发送包里只把同场景人物列为当前可见人物。
3. 做简单的“日程提醒”结构，但先不自动改变量。
4. 稳定后，再考虑不同场景角色的后台日程结算。

## 设计原则

角色有自己的生活节奏，但当前剧情优先。

日程负责制造生活感和叙事压力，不负责粗暴抢走角色。

## 2026-07-26 讨论备份：暂缓核心角色整日日程

本次重新讨论时，目标被进一步明确为：让阿黛拉、绵暖这类核心角色拥有“一整天都存在于背景中”的生活线，避免长对话后模型忘记早先安排过的中午、下午或晚间日程。

讨论中的候选方案类似 `<AUTO>` 后台块：每回合在正文后输出核心角色、行为链、当前想法、24 小时日程表等内容。它的好处是角色差异会更强，每个角色每天都有独立安排；但缺点也很明显：输出内容很大，格式压力高，还会增加正文生成时的维护负担。如果日程只存在聊天上下文里，长回合后仍然可能被遗忘。

因此暂定结论：

- 暂时不实现完整核心角色日程系统。
- 不把大段 CoT/思维链式内容作为正式输出格式。
- 如果以后重启此功能，应把它设计成“可存档的角色后台日程”，而不是依赖模型记忆。
- 前端或世界书保存完整日程表，每回合只计算并发送当前命中的提醒。
- 正文只负责自然承接提醒，不负责重新规划整天。

建议未来分层：

```text
普通背景客人：轻量客流与行为池
普通配角：伪活人化行为库，做区域背景动作
核心角色：独立日程伪活化，拥有当天固定生活节奏
```

如果以后做 MVP，优先不要自动改变量：

1. 建立核心角色日程库，先只支持阿黛拉、绵暖。
2. 前端按日期、星期、时间判断当前命中的日程。
3. 生成发送包时只输出“日程提醒”，不输出完整 24 小时表。
4. 如果角色与主角同场景，提醒正文自然处理她是否告辞、留下、迟到或改约。
5. 如果角色不在同场景，第一版也先只提醒，不自动移动；稳定后再考虑后台结算位置。

核心判断：这个系统的价值不是让模型每回合多写一大段，而是把“角色下午本来该做什么”存到前端/世界书里，让时间到了以后系统能重新提醒，从而减少长聊天造成的遗忘。
